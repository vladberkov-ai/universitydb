Parent kill/reap and SDK receive the same min(operation timeout, remaining run time). Aggregate reserved tokens derive from5×(12000+32768)=223840. The generic official25000-token starting guidance motivates output headroom; longer researched600/300s alternatives were rejected for this bounded interactive slice pending measured authorized runs. Incomplete/timeouts remain visible failures, not grounds to disable limits.

Unknown coverage remains a live blocker; no paid compatibility/token-count probe now. If coverage cannot be established within this envelope, stop for a bounded policy/accounting revision rather than silently claim a hard cap.
- **Preserve version1 spending history**, not ledger reset/migration: monetary model/cap/rates stay pinned; variable per-attempt holds already store dollars independently of token-policy defaults. Rates must cover the maximum applicable input category (including cache writes and applicable regional/context premiums), not merely ordinary input; output rate covers all generated reasoning/visible tokens. Retain max(reservation, observed) per attempt, even on unknown usage/timeouts, with the existing stable-lock atomic ledger. No cap, rates or billing verification flag is installed by code.
