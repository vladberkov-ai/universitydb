# Критерии по исходнику: исправление CHAT-007

Повторно прочитан исходный PDF (частный источник; не экспортирован), все четыре страницы.
Источник коррекции: CHAT-007 (частный источник; не экспортирован).
CHAT-008 подтвердил соответствие исправленной матрицы заданию и поручил подготовить CLI-пакет. Матрица принята как основа передачи; это не подтверждение выполненных проверок.
Предыдущая версия (частный источник; не экспортирован) сохранена для истории.

## Исправление
Предыдущий ответ подменял обсуждение соответствия заданию согласованием ряда дополнительных
предметных правил и численного порога. Эти правила были помечены proposed, но не являются
условиями исходного задания. Порог 27/30 не обоснован PDF и не может разрешать невыполнение
обязательного требования. Он снят с текущего предложения приёмки.
Последний краткий перечень также не покрывал явно имена студентов/преподавателей, независимость
ядра от схемы, противоречивые результаты и production considerations.

PDF называет тестовый раздел Unit Tests и включает туда E2E. Разделение на unit/integration/E2E
допустимо как организация проверок, но не отменяет ни одного направления.
Multi-step reasoning не означает обязательное фиксированное число SQL-запросов; несколько узлов
графа сами по себе не доказывают рассуждение. Нужен содержательный сложный пример с объяснимыми шагами.

## Отдельные источники обязательств
Согласованный пользователем объём (CHAT-006 / ADR-CHAT-002): простой экран, зависимый сценарий,
вторая небольшая схема. Это способы демонстрации, не дословные условия PDF.
Пользовательские требования: фактические prompts, все архитектурные решения с причинами,
wiki/CLI-владение, Git evidence и срок вечером 7 ноября; сам PDF требует публикацию до интервью.
Ранее предложенные процедуры clean clone/manual E2E и проверки SHA — способы подтверждения сдачи,
а не буквальные строки исходника.

## Что не следует утверждать сейчас
PDF не задаёт шкалу 0–100, допустимость NULL, единственную итоговую оценку, политику пересдач,
правило выбора семестра по умолчанию, веса среднего, точную схему таблиц или количественный eval-порог.
Фраза о преподавателе курса в семестре должна поддерживаться моделью; полный набор кардинальностей
и ограничений необходимо обосновать при проектировании, не приписывая его исходнику.
Read-only/лимиты — инженерные предложения безопасности; PDF требует объяснения security,
но не задаёт конкретного механизма.

## Следующий шаг по плану
Использовать эту матрицу как основу требований и доказательств, сохранив принятый объём.
При подготовке самостоятельного задания CLI перечислить недоопределённые предметные правила
как вопросы для архитектурного предложения с вариантами/причинами. Архитектура возвращается
в чат для разбора до реализации. Численный eval-план при необходимости обосновать отдельно;
процент успешности не закрывает отсутствующее обязательное поведение.
H-003 остаётся старым неизменённым draft; нужен новый актуальный пакет перед передачей.
Реализация и OMX в этом исправлении не запускаются.
